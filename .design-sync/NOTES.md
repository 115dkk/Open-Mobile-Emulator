# design-sync notes (Open Mobile Emulator)

Repo-specific facts a future sync needs. One bullet per gotcha; append, never rewrite history.

## Layout

- The design system is not a published package. It is the app's own component library at
  `host/ui/src/components/*.tsx` (React 19, strict TS, Vite, hand-written token CSS, no component
  library dependency). There is no library build, so the converter runs in synthesized-entry mode
  (`srcDir: ui/src/components`, `tsconfig: tsconfig.app.json`); package root is `host/`
  (`--node-modules ./host/node_modules`, run from the repo root).
- Styles: `ui/src/styles/tokens.css` (tokens, `@font-face`), `app.css` (base + component rules,
  `ome-*` prefix; it `@import`s `screens.css` first, so the CSS closure includes screen layouts).
- Fonts are bundled files under `ui/public/fonts/` referenced by absolute `/fonts/...` URLs from
  `tokens.css` (Vite serves `public/` at `/`). Listed in `cfg.extraFonts` so the converter copies
  the woff2 files into `fonts/`.
- Guidelines: `docs/DESIGN.md` (Korean design contract: tokens, type, spacing, motion, icons,
  state grammar, overlay, copy rules) via `guidelinesGlob: ../docs/DESIGN.md`.
- Playwright for the render check: the repo pins `@playwright/test` 1.63.0 (chromium build 1243);
  `playwright@1.63.0` is installed into `.ds-sync/` so `package-validate.mjs` can import it. The
  headless shell 1243 is in `%LOCALAPPDATA%/ms-playwright`.

## Known render warns

- `[FONT_MISSING] "Cascadia Mono" (--font-mono)`: the mono stack is `"Sarasa Mono K", Consolas,
  "Cascadia Mono", monospace`; Sarasa Mono K ships in `fonts/`, the other two are Windows system
  fallbacks and are not meant to ship. Accepted, not a substitute.
- `[GRID_OVERFLOW]` fired once for SettingRow, ScreenHeader, EmptyState, IssueNotice, ProgressBar and
  Segmented (wide rows); resolved with `overrides.<Name>.cardMode = column`. Dialog (portal + fixed
  backdrop) and Rail (full-height column) use `cardMode: single` with a viewport.
- The converter's `.d.ts` extractor caps unions at 24 members; the 37-name `IconName` union
  collapses to `unknown` unless `dtsPropsFor` pins it (see config).

## Re-sync risks

- `host/types/` is regenerated by `node .design-sync/prebuild.mjs` (the `buildCmd`); run it before
  the converter after any component or stylesheet change. Stale declarations silently ship old
  props contracts.
- `dtsPropsFor` bodies in `config.json` are hand-maintained copies for eleven components: the six
  that carry the `IconName` union (the extractor caps unions at 24 members and emitted `unknown`),
  IssueNotice (inline props type, emitted `[key: string]: unknown`), and Segmented, Select, StepList,
  Rail (generic or named item types the extractor left undeclared). When `IconName` or any of those
  props change in `host/ui/src/components/`, update the bodies; the icon list is the `IconName`
  union in `Icon.tsx`, in order.
- `componentSrcMap` enumerates the 19 components because there is no `.d.ts` entry to discover them
  from; a new component in `host/ui/src/components/` must be added there (and to `index.ts`).
- Previews import `open-mobile-emulator`, which the converter aliases to the synthesized bundle;
  the package is never published, so nothing outside this sync resolves that name.
- The guidelines copy of `docs/DESIGN.md` is verbatim; it is Korean and the design agent reads it as
  the composition guide.
- Playwright: `.ds-sync/` needs `playwright@1.63.0` (matches the cached headless shell 1243). A
  playwright upgrade in `host/package.json` needs a matching browser build in the cache.
