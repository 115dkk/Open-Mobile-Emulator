# Play 스토어에서 트릭컬 로비까지

2026-10-09, 설치된 Open Mobile Emulator 0.1.4의 Android 13 게스트에서 확인했다.
스토어 업데이트는 [전날의 시험](../20261008/play-store.md)에서 `10644 → 10655`로 완료했고,
이번에는 Windows 컴퓨터 유즈로 OME를 시작해 스토어 상세 화면, 게임 실행, 추가 데이터,
Google 로그인과 로비를 관찰했다. 사용자가 OME 안의 Google 로그인을 명시적으로 허용했다.

## 확인된 결과

| 단계 | 결과 | 증거 |
|---|---|---|
| OME 재실행 | S26 Ultra 모델·지문과 GLES 3.2 보고 유지 | `lobby-runtime.json` |
| Play 스토어 | 트릭컬 상세 페이지에 Play 버튼, 호환 불가 안내 없음 | `01-play-store-ready.png` |
| 게임 추가 데이터 | 356.3MB 다운로드 안내에서 다운로드 선택, 저장된 데이터로 재실행·정리 완료 | `02-game-data-processing.png` |
| Google 로그인 | 게임의 로그인 선택 화면에서 Google을 선택한 뒤 정상 타이틀 표시 | `03-google-login-title.png` |
| 로비 | 기존 Google 계정의 레벨 129 로비 표시 | `04-google-login-lobby.png` |
| 설치 출처 | versionCode 10655, `installerPackageName=com.android.vending` | `lobby-runtime.json` |

앱은 Play 스토어의 Play 버튼으로 실행했다. 계정·게임 데이터를 초기화하지 않았다.
저장된 Google 계정을 사용했으며 비밀번호 입력이나 새 계정 생성은 필요하지 않았다.
파일 증거의 Android 화면은 화면 관찰 직후 adb의 읽기 전용 `screencap`으로 저장했다.

## 입력 경로 대조

Windows 컴퓨터 유즈가 누른 다운로드 버튼의 위치를 USB 태블릿 이벤트와 대조했다.
관찰한 무대는 약 1192×660 픽셀이고, 버튼 위치에 대응하는 값은
`ABS_X=19455`, `ABS_Y=26987`이었다. 화면 좌표와 비례한 값이다. 닫기 버튼도
`31525,1433`으로 대응했다. 이전 QEMU 좌표 배율 수정은 변경하지 않았다.

컴퓨터 유즈의 일부 마우스 클릭은 약 18~20ms의 DOWN/UP으로 전달됐지만 게임 버튼이 반응하지 않았다.
출석·안내 팝업은 같은 위치의 180ms Android 터치 입력으로 닫았다. 모든 안내 뒤의 로비를 다시 캡처했다.
입력 종류와 누름 시간이 함께 달라진 대조이므로, 원인이 오직 누름 시간이라고 결론내리지는 않는다.
QMP는 실행 중인 OME가 연결을 소유해 별도 시험 연결이 시간 초과됐고, 그 경로에서는 입력을 전달하지 못했다.

## 영상 경로

기본 Android 소프트웨어 영상 디코더의 기존 충돌이 재현됐다. FFmpeg 우선순위를 시험했지만
YUV 평면을 처리하는 virgl 경로에서 그래픽 컨텍스트 오류가 발생해 원래 값 `4294967295`로 되돌렸다.
그 상태로 다시 실행한 뒤 데이터 정리·Google 로그인·로비가 정상 표시됐다. 대체 디코더 설정은
제품 프로필에 추가하지 않았다. 앱 안 영상 재생 문제는 여전히 별도 제한 사항이다.

## 검증 이후 제품 정리

사용자 결정에 따라 비인증 기기 등록 화면, GSF ID 조회·복사, 등록 페이지 열기, 계정 수 폴링,
호스트의 Google 계정 추가 명령과 관련 Tauri 권한을 제거했다. 로그인은 게스트 앱 안에서 진행한다.
기존 `guest.json` 스키마 1을 읽는 호환 변환은 디스크와 나머지 설정을 보존하고, 새 스키마 2에서는
폐기한 등록 메타데이터를 저장하지 않는다.

Tauri 생산 빌드(`build --no-bundle`)를 설치된 `ome.exe`에 반영했다.
새 실행 파일의 SHA-256은
`b8e604db3d5abe4fd924749127e7abd1f8ba586c890bb2bcd96471e046f90179`다.
기존 실행 파일과 메타데이터는 각각 `*.before-registration-removal-20261009`로 백업했다.
새 설치본에서 기존 게스트 부팅·앱 목록을 확인했고, 실행 중인 설정 화면의 여덟 섹션에
등록 안내가 없는 것을 컴퓨터 유즈로 확인했다. 이어 같은 설치본에서 저장된 Google 로그인 세션으로
[로비에 다시 진입](05-lobby-after-registration-removal.png)했다. 실제 메타데이터도 스키마 2로 저장되며
폐기한 필드가 없다. [설치본 검증 기록](native-acceptance.json)에 결과를 남겼다.

검사: Rust 전체 워크스페이스 테스트와 Clippy(`-D warnings`), 프런트 테스트 291개,
Tauri 권한·빌드 분리 검사 9개, Python 프로필 시험 3개, 매니페스트·SPDX·금지 파일·스크립트
문법 검사를 통과했다. 계약은 11로 올렸고 해당 인터페이스 시험 47개도 다시 확인했다.
새 Android 15 이미지의 전체 빌드는 이 호스트 실행 파일 빌드에 포함되지 않는다.

이 시험은 기존 계정에서의 업데이트와 로비 진입 증거다. 신규 계정의 첫 로그인, 인앱 결제,
Google의 기기 인증 판정, 다른 게임의 지원 여부는 각각 별도 검증 대상이다.
