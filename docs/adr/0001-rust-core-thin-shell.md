# ADR-0001: Rust 코어가 지능을 갖고 Tauri 껍데기와 웹뷰는 얇다

상태: 채택, 2026-09-26.

## 배경

D7로 프런트엔드 스택이 Tauri 2 + Rust로 정해졩다(`docs/DECISION-frontend.md` 8절). 사용자는
같은 날 "Tauri에는 지능을 최대한 주지 않고 Rust가 지능을 가지는 쪽"으로 설계하라고 했다.
사용자의 두 Tauri 제품은 이미 그 모양(런타임 크레이트가 판단을 소유하고 껍데기는 명령을
넘기며 웹뷰는 상태를 그린다)으로 만들어져 있다.

## 결정

- 제품 논리는 `host/crates/` 아래의 Rust 크레이트가 소유한다. 껍데기 `host/app`은
  `ome-runtime` 하나만 부르고, 창 생성, 입장 검사, 이벤트 전달, 트레이만 한다.
- 웹뷰는 Rust가 만든 `AppSnapshot`을 그리는 순수 함수다. 웹뷰에는 파일, 네트워크, 프로세스,
  대화상자 권한이 없다. 필요한 모든 것은 타입이 정해진 명령으로 Rust에 요청한다.
- Tauri 플러그인은 Rust 쪽에서만 부른다(알림, 단일 인스턴스, 업데이터). 웹뷰 권한 목록에
  플러그인 명령을 넣지 않는다(ADR-0003).
- QEMU, adb, dism은 별도 프로세스다(D5, R4). 링크하거나 소스를 복사하지 않는다.
- 핵심 크레이트는 `tokio`에 의존하지 않는다. 동기 표준 라이브러리와 스레드로 쓰고, 껍데기가
  `spawn_blocking`으로 부른다. 이유는 테스트 어댑터를 꽂기 쉽고 Tauri 런타임 버전에 묶이지
  않기 때문이다.

## 결과

- 제품 논리 테스트는 QEMU 없이 돈다. `ome-runtime` 통합 테스트가 명령에서 스냅숏까지를
  덮는다.
- 웹뷰를 다른 렌더러로 바꾸거나 CLI를 붙여도 Rust 크레이트는 그대로다.
- 웹뷰가 판단을 하지 않으므로 화면 코드 리뷰는 표시와 접근성에만 집중한다.
- 대가는 명령 종류마다 Rust 타입과 TypeScript 형을 함께 갱신해야 한다는 것이다.
  `contracts.ts`와 Rust 형의 동기화는 스냅숏 JSON 픽스처 테스트로 지킨다.
