# Open Mobile Emulator 디자인 계약

작성 2026-09-26. 이 파일이 시각 규칙의 정본이고, `host/ui/src/styles/tokens.css`와 claude.ai의
디자인 시스템 "Open Mobile Emulator"는 여기 값을 그대로 옮긴 사본이다. 값이 어긋나면 이 파일을
믿고 사본을 고친다. 문구 규칙은 마지막 절에 있고, 화면 목록은 `M2-SCREENS.md`에 있다.

## 1. 방향

게임 화면을 담는 조용한 윈도우 도구다. 화면의 주인은 무대(게스트 화면)이고, 껍데기는 그
둘레에서 상태를 말하고 물러난다. 어둡고 채도가 낮은 회색 위에 하늘색 하나만 강조로 쓴다.
카드와 그라데이션, 장식 숫자, 마케팅 문장은 없다. 윈도우 11 관용을 따르고 창 캡션은
윈도우 기본을 쓴다(커스텀 캡션 없음).

첫 테마는 어두운 테마다. 게스트 화면 둘레가 밝으면 게임 화면과 대비가 커서 눈이 피로하고,
에뮬레이터 사용자가 기대하는 모습도 어두운 쪽이다. 밝은 테마는 시스템 설정을 따를 때만 쓰고
같은 정성으로 만든다. 무대 둘레(`stage-frame`)는 두 테마 모두 가장 어두운 값이다.

|---|---|---|---|
| `--bg` | `#14171b` | `#f3f5f7` | 창 배경 |

| `--text` | `#e6eaee` | `#1a222b` | 본문 |

규칙. 색은 이 열여섯 토큰과 그 알파 변형으로만 쓴다. 두 번째 강조색과 보라색은 쓰지 않는다.
`success`, `warning`, `danger`는 상태에만 쓰고 장식에 쓰지 않는다. 배경에 순수한 검정과
흰색은 쓰지 않는다. 대비는 본문과 보조 문장이 자기 배경에서 4.5:1을 넘긴다(어두운 테마
`muted`/`surface` 6.7:1, 밝은 테마 5.1:1, `on-accent`/`accent` 7.0:1과 5.3:1). 강제 색상 모드에서는
시스템 색과 실제 테두리를 쓴다.

## 3. 활자

- 가족 `--font-ui`: `"Pretendard", "Malgun Gothic", "Segoe UI", sans-serif`. Pretendard(OFL)의
  완성형 한글 + 라틴 서브셋 WOFF2 400/500/600/700을 저장소에 담아 오프라인으로 싣는다(R10).
  합성 굵기는 쓰지 않는다.
- 가족 `--font-mono`: `"Sarasa Mono K", Consolas, "Cascadia Mono", monospace`. 경로, 해시,
  logcat, adb 출력에 쓴다. Sarasa Mono K(OFL) 서브셋 400/700을 담는다.
- 크기 표(px / 굵기 / 행간).

| 토큰 | 값 | 자리 |
|---|---|---|
| `--type-title` | 22 / 600 / 1.3 | 화면 제목, 마법사 단계 제목 |
| `--type-section` | 16 / 600 / 1.4 | 절 제목 |
| `--type-body` | 14 / 400 / 1.5 | 본문, 컨트롤, 목록 |
| `--type-label` | 13 / 600 / 1.35 | 입력 라벨, 표 머리 |
| `--type-caption` | 12 / 400 / 1.4 | 시각, 크기, 버전 같은 메타데이터. 행동에 필요한 글은 여기 두지 않는다 |
| `--type-mono` | 13 / 400 / 1.5 | 경로, 해시, 로그 |
| `--type-readout` | 14 / 500 / 1.4, `tabular-nums` | 바뀌는 숫자(진행률, fps, 남은 시간) |

제목에는 `text-wrap: balance`, 본문에는 `text-wrap: pretty`. 한국어는 `word-break: keep-all`,
넘치는 토큰만 `overflow-wrap: anywhere`. 글이 안 들어가면 줄여 쓰거나 자리를 넓히고 글자
크기를 낮추지 않는다. 시스템 글자 크기 배율을 막지 않는다.

## 4. 간격과 기하

- 4px 기준. `--space-1` 4, `--space-2` 8, `--space-3` 12, `--space-4` 16, `--space-5` 20,
  `--space-6` 24, `--space-8` 32, `--space-10` 40, `--space-12` 48.
- 반지름. `--radius-control` 6px(버튼, 입력, 칩), `--radius-card` 12px(패널, 대화상자),
  `--radius-stage` 8px(무대 둘레). 바짝 겹치는 요소는 바깥 = 안 + 사이 여백.
- 창. 기본 1280x800, 최소 960x600. 왼쪽 아이콘 레일 64px(아이콘 위, 라벨 아래), 무대 위 도구
  막대 44px, 아래 상태 줄 28px. 무대는 남는 공간을 전부 쓰고 게스트 화면 비율을 지키며 가운데
  놓인다.
- 히트 영역. 데스크톱 컨트롤 40x40px 이상, 무대 도구 막대 아이콘 버튼 40x40, 마법사의 주
  버튼 44px 높이. 두 컨트롤의 히트 영역은 겹치지 않는다.
- 깊이. 구조는 선으로, 떠 있는 것만 그림자로. `--shadow-surface`는 어두운 테마
  `0 1px 2px rgb(0 0 0 / .24), 0 6px 20px rgb(0 0 0 / .18)`, 밝은 테마
  `0 1px 2px rgb(26 34 43 / .06), 0 6px 20px rgb(26 34 43 / .08)`. 대화상자와 토스트에만 쓴다.
  무대 둘레는 `inset 0 0 0 1px var(--line)`.
- 이미지와 스크린샷 미리보기에는 1px 윤곽 `oklch(0 0 0 / .1)`(밝은 테마), `oklch(1 0 0 / .1)`
  (어두운 테마).

## 5. 움직임

`--motion-fast` 120ms, `--motion-normal` 180ms, `--ease-standard` cubic-bezier(.2, 0, 0, 1).
전이는 `opacity`, `transform`, `background-color`, `box-shadow`에만 걸고 `transition: all`은
쓰지 않는다. 버튼 누름은 `scale(.96)`. 자주 일어나는 상호작용(호버, 키 입력, 진행률 갱신)에는
맞춤 애니메이션을 두지 않는다. 마법사 단계 전환만 4px 위로 올라오며 나타나는 한 번의
전이를 갖고, 나가는 쪽은 더 조용하다. `prefers-reduced-motion`에서는 전이를 없애고 상태와
포커스는 그대로 둔다. 움직임은 언제나 색이나 글자로도 같은 상태를 말한다.

## 6. 아이콘

Lucide(ISC) 아이콘을 인라인 SVG로 쓰고 `currentColor`로 칠한다. 상태(호버, 선택, 비활성)는
CSS 색과 불투명도로 만들고 별도 자산을 두지 않는다. 400 글자 옆은 1.5px 획, 600 글자 옆은
2px 획. 기본은 윤곽선이고 채움은 활성 상태에만 쓴다. 상태 점은 채운 원 + 옅은 후광이고
꺼짐은 같은 모양을 흐리게 한다. 아이콘만 있는 버튼에는 접근 가능한 이름을 붙인다. 앱
아이콘은 자체 제작 마크(휴대폰 윤곽 안의 재생 삼각형)이고 Android, Google, Bliss, 게임의 표지를
쓰지 않는다(R6).

## 7. 상태 문법

- 게스트 상태 점 하나가 `Stopped`(흐림), `Starting`(강조색 맥동, 축소 동작 모드에서는 정지),
  `Running`(성공색), `Restarting`(경고색), `Failed`(위험색)를 말하고 옆 글자는 같은 뜻을
  되풀이하지 않고 다음 행동을 말한다.
- 비활성 컨트롤은 불투명도 .45에 라벨을 유지하고 호버와 누름 반응이 없다. 아직 연결되지 않은
  기능은 비활성 버튼이 아니라 없는 버튼이다. 가짜 진행률, 가짜 연결 상태를 그리지 않는다.
- 전체 화면을 덮는 동의 화면(WHPX 켜기)은 Esc와 보이는 버튼으로 언제나 나갈 수 있고 나가는
  길을 글자로 적는다. 나간 것은 취소이고 실패가 아니다. 카운트다운을 두지 않는다.
- 진행 중인 긴 작업(ISO 내려받기, 설치)은 진행률, 속도, 남은 양을 `tabular-nums`로 보이고
  취소 버튼을 항상 둔다.

## 8. 문구

합니다체. 결과와 다음 행동을 말하고 내부 이름(QMP, WHPX, qcow2, 프로세스 이름, 설정 키)은
화면에 내지 않는다. 사용자가 알아야 할 시스템 이름은 윈도우가 쓰는 이름 그대로 쓴다(예:
"Windows 하이퍼바이저 플랫폼"). 오류는 무엇이 일어났고 무엇을 하면 되는지 두 문장으로 쓰고
원문은 세부 정보와 로그에 둔다. 안전이나 정확성을 장담하는 문장, 자기 칭찬, 감성 문구,
이모지는 쓰지 않는다. 게임 이름과 이미지는 제품 화면에 심지 않는다(R6). 게스트에서 읽은 앱
이름은 사용자 데이터이므로 그대로 보인다.
