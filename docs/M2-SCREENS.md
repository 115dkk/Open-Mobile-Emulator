# M2 화면 목록

작성 2026-09-26, 개정 2026-09-27. 구현 전에 어떤 화면을 만들지 정하는 문서다. 기능 명세는
`CLAUDE.md` 5절 M2, 시각 규칙은 `DESIGN.md`, 낱말은 `CONTEXT.md`, 웹뷰가 받는 자료와 보내는
명령은 `ARCHITECTURE.md` 8절(계약 두 번째 판)에 있다. 각 화면은 스냅숏(`AppSnapshot`)의 어느
부분을 그리고 어떤 명령(`Command`)을 보내는지로 정의한다. 목업은 claude.ai 디자인 캔버스에
있고 이 문서의 화면 번호를 그대로 쓴다.

개정 2026-09-27의 내용은 10절의 사용자 결정, 문구 전면 수정(9절), S1.7 삭제, 하드웨어 한도의
호스트 유래, 표시 화면의 해상도와 주사율과 수직 동기화, 설정의 adb와 루팅이다.

## 0. 창 구조

창은 하나다. 윈도우 기본 캡션 아래에 왼쪽 아이콘 레일(64px)과 본문이 있다. 레일 항목은
`무대`, `앱`, `입력`, `표시`, `설정` 다섯 개이고 아래쪽에 상태 점과 버전이 있다. 첫 실행
마법사(S1)는 레일 없이 본문 전체를 쓰는 별도 상태이고, 마법사가 끝나기 전에는 레일이 보이지
않는다. 기본 크기 1280x800, 최소 960x600.

트레이 아이콘은 항상 있다. 창을 닫으면 기본으로 운영체제를 끄고 앱을 종료한다(사용자 결정
2026-09-27: 트레이에 남는 기본값은 사용자가 껐다고 믿는 운영체제가 메모리를 계속 차지하게
한다). 설정에서 `트레이로 내리기`를 고른 경우에만, 운영체제가 실행 중일 때 창을 닫으면 트레이로
내려가고 그 사실을 토스트로 한 번 알린다.

화면에서 쓰는 말은 `운영체제`(안에서 도는 안드로이드)와 `가상 머신`(그것을 돌리는 VM)이다.
`게스트`는 코드와 문서의 말이고 화면에는 나오지 않는다(`DESIGN.md` 9절).

## 1. 첫 실행 마법사 (S1)

한 화면에서 단계가 바뀐다. 위에 단계 표시(1/7 형태의 점과 현재 단계 이름), 가운데 단계 본문,
아래 주 버튼과 보조 버튼. 모든 단계에 `나중에 하기`(마법사를 닫고 무대 화면으로 가되 진행
상태를 저장)가 있다. 단계 순서와 건너뛰기 규칙은 `ome-wizard`가 소유한다. 구글 계정 안내
단계는 없다(10절 4번).

| 단계 | 보이는 것 | 동작 | 규칙 |
|---|---|---|---|
| S1.1 호스트 점검 | 제목 `호스트 점검`. 판정 한 문장: `이 PC에서는 Open Mobile Emulator를 사용할 수 있습니다.` 또는 `이 PC에서는 Open Mobile Emulator를 사용할 수 없습니다.`(막힘 행이 하나라도 있을 때). 그 아래 항목별 상태 표. 라벨은 `CPU 가상화`, `Windows 하이퍼바이저 플랫폼`, `Windows 다시 시작`, `가상 머신 구성 요소`(QEMU와 펌웨어), `앱 설치 도구`(adb), `디스크 공간`. 각 행은 상태 점 + 이름 + 한 문장. 문장은 라벨을 되풀이하지 않는 판정이다(`Windows 다시 시작 / 필요하지 않습니다.`, `디스크 공간 / 설치에 충분한 여유가 있습니다.`). 설치할 수 있는 행은 다시 시작 행까지 모두 초록 점이다(사용자 결정 2026-09-30). 마지막에 확인 시각 | `다시 확인`, `계속`(막힘이 없을 때만) | 아무것도 바꾸지 않는다. 그 사실은 화면에 적지 않는다 |
| S1.2 하이퍼바이저 활성화 | 제목 `하이퍼바이저 활성화`. 앞 문장 `Open Mobile Emulator를 사용하려면 하이퍼바이저를 활성화해야 합니다.` 세 항목: `하이퍼바이저를 활성화합니다.` / `활성화 시 관리자 권한이 필요합니다.` / `활성화 후 다시 시작해야 할 수 있습니다. 작업을 미리 저장해두십시오.` 주의 상자 한 줄: `활성화하면 같은 PC에서 커널 안티치트를 쓰는 게임이 실행되지 않을 수 있습니다.`(KNOWN_LIMITATIONS) | `활성화`(관리자 권한 요청), `지금은 건너뛰기`. Esc로도 나가고 그 사실을 한 줄로 적는다 | R9. 이미 켜져 있으면 단계를 건너뛴다. `tcg`로는 진행할 수 없다 |
| S1.3 다시 시작 필요 | `하이퍼바이저를 활성화했습니다. PC를 다시 시작한 뒤 앱을 다시 열면 이어서 진행합니다.` | `닫기`. 자동 재부팅 버튼은 없다 | R9(예고만 한다) |
| S1.4 운영체제 이미지 다운로드 | 제목 `운영체제 이미지 다운로드`. 앞 문장 `운영체제 이미지를 공식 배포처에서 다운로드합니다. 연결이 끊겨도 다시 이어받을 수 있습니다.` 위에 이미지 카드(`ImagesView.profiles`, 최신 버전이 앞. 카드는 `안드로이드 13` 같은 이름, 버전, 크기, 상태 칩 `검증됨` / `검증 전` / `지원 종료`, 검증된 게임 수. `recommended`인 카드가 기본 선택). 아래에 고른 이미지의 파일 이름, 출처(SourceForge 공식 프로젝트), 크기, 진행률 막대, 속도와 남은 양. 단계 표시 `다운로드 중 → 무결성 확인 → 완료` | 카드 선택(`guest_image_select`), `다운로드`, `취소`, 이어받기는 자동 | R2, R10. 매니페스트 밖 URL 없음. 프로필은 `manifests/images/`(ADR-0004) |
| S1.5 운영체제 설치 | 디스크 크기 선택(32/64/128 GB, 여유 공간 표시), 그 뒤 무대에 설치기가 뜨고 옆에 이미지 프로필의 설치 안내(`WizardView.install_guide`) 여섯 단계 | `디스크 만들기`(`guest_create`), 설치 끝난 뒤 `설치 완료` | 설치기 조작은 사용자가 한다 |
| S1.6 첫 부팅 | 무대에 부팅 화면, 옆에 단계 목록 `가상 머신 시작` / `화면 연결` / `운영체제 부팅` / `기능 확인`. 각 줄은 명사구이고 왼쪽 기호가 진행과 완료를 말한다. 능력 조사(ADR-0004)의 항목이 하나씩 확인 표시로 바뀐다. 부팅 뒤 `미디어 볼륨과 기본 표시 프리셋을 적용했습니다.` 한 줄 | 자동 진행, `취소` | KNOWN_LIMITATIONS(볼륨). 조사에 실패한 능력은 뒤 화면에서 없는 버튼이 된다 |
| S1.7 앱 설치 | 제목 `앱 설치`. 앞 문장 `앱 파일을 지금 설치할 수 있습니다.` 파일 놓기 영역(APK, XAPK, APKS), `파일 고르기`, 설치 진행과 결과 목록. 목록 아래에 작게 `앱 화면에서도 추가로 설치할 수 있습니다.` | `파일 고르기`(Rust가 대화상자를 연다), `건너뛰기`, `완료` | 게임 이름을 화면에 심지 않는다(R6) |

끝나면 무대 화면(S2)으로 가고 마법사는 다시 나타나지 않는다. 처음부터 다시 하는 길은 설정의
`다시 설치`(운영체제 디스크를 지우고 같은 이미지로 다시 설치)뿐이다. 마법사만 다시 여는 기능은
없다(10절).

## 2. 무대 (S2)

기본 화면이다. 운영체제 화면이 놓이는 무대와 그 위 도구 막대, 아래 상태 줄로 이루어진다.
상태 점 옆 글자는 명사구다.

- `Stopped`: 무대 자리에 큰 `시작` 버튼 하나와 `마지막 실행 2026-09-26 19:58, 정상 종료` 한 줄.
  상태 줄은 `시작 가능`. 마지막 종료가 비정상이면 그 사실과 `로그 보기`가 함께 있다.
- `Starting`: 무대는 어둡고 가운데 단계 목록 `가상 머신 시작` / `화면 연결` / `운영체제 부팅`.
  왼쪽 기호가 완료와 진행 중을 말하고 문장은 없다. 상태 줄은 `부팅 중`. `취소`가 있다.
- `Running`: 무대에 운영체제 화면이 담기고 그 위에 오버레이 창이 표지를 보인다. 상태 줄은
  `실행 중`이고 그 밖의 안내 문장은 없다. 도구 막대에는 `스크린샷`, `볼륨`, `표시 프리셋`,
  `매핑 표시 켬/끔`, `매핑 편집`, `다시 시작`, `끄기`가 아이콘 버튼으로 있고, 상태 줄에는 상태
  점, 안드로이드 버전, 해상도와 배율, `앱 관리 연결됨`, 적용된 입력 프로필 이름(자동 적용이면
  전경 앱 이름과 함께), 일시 중지 중이면 `매핑 일시 중지 (F12)`가 있다. fps는 기본으로 보이지
  않고 설정에서 켠다(10절 2번).
- `Restarting`: 상태 줄 `다시 시작 중`. 무대는 어둡다.
- `Failed`: 제목은 원인별로 다르다(`GuestView.last_exit.kind`). `startFailed`는 `가상 머신이
  시작하지 못했습니다.`, `bootTimeout`은 `운영체제 부팅에 실패했습니다.`, `crash`는 `크래시가
  일어났습니다.` 본문은 한 줄 `다시 시작을 시도할 수 있습니다. 반복될 경우 로그를 첨부해 문제를
  보고하십시오.` 버튼 `다시 시작`, `진단 묶음 내보내기`, 펼침 `세부 정보`(로그 파일 경로).
  상태 줄은 `실패`.
- 창 담기가 실패하면(2안) 무대 자리에 `운영체제 화면은 별도 창에 있습니다.`와 `창 앞으로`
  버튼이 놓인다.

## 3. 앱 (S3)

운영체제에 설치된 앱 목록(아이콘 없이 이름과 패키지, 버전, 설치일), 각 행에 `실행`, `제거`(확인
대화상자가 뜨지만 그 사실은 목록에 적지 않는다), 위에 `설치`(파일 고르기 또는 끌어 놓기)와
검색. 설치 진행은 목록 위의 한 줄로 보인다. 목록 아래는 `앱 3개.` 한 줄뿐이다. 운영체제가 꺼져
있으면 목록은 마지막 값을 흐리게 보이고 동작 버튼은 없다. 스크린샷 저장은 무대 도구 막대에
있고 여기서는 `스크린샷 폴더 열기`만 둔다.

## 4. 입력 (S4)

두 부분이다. 레일의 `입력` 화면과, 무대 위의 오버레이 편집기(ADR-0005).

**입력 화면(S4)**: 왼쪽에 프로필 목록(동봉 프리셋 + 사용자 프로필. 각 행에 이름, 대상 앱 이름,
바인딩 수, 자동 적용 표시), 오른쪽에 고른 프로필의 바인딩 표(입력, 동작 종류, 자리, 설명)와 그
위에 `현재 화면` 미리보기(운영체제가 실행 중이면 현재 화면, 아니면 마지막 스냅샷. 라벨은 둘 다
`현재 화면`이고 꺼져 있을 때만 `화면 스냅샷`). 미리보기 위의 안내는 한 줄 `화면 위의 자리를
클릭하고 설정할 키를 누르십시오.` 동작은 `새 프로필`, `복제`, `이름 바꾸기`, `삭제`, `대상 앱
지정`(설치된 앱 목록에서 고른다), `무대에서 편집`(S4-오버레이로 간다), `자동 적용` 토글.
일시 중지 단축키는 설정에 있다. 운영체제가 꺼져 있어도 표는 편집할 수 있고 자리는 논리 좌표라
해상도와 무관하다.

**오버레이 편집기(S4-오버레이)**: 운영체제 화면 위에 현재 프로필의 표지가 보인다. `매핑 편집`을
누르면 편집 모드가 되어 위쪽에 도구 띠(표지 종류 다섯 개: 탭, 조이스틱, 스와이프, 마우스 버튼,
휠. 그리고 `저장`, `되돌리기`, `편집 끝`)가 뜨고 클릭이 오버레이로 간다. 빈 자리를 누른 뒤 키를
누르면 탭 표지가 생기고, 표지를 끌어 옮기고, 조이스틱은 반지름 손잡이를 끌어 크기를 바꾼다.
표지를 다시 누르면 홀드 여부, 스와이프 끝점과 지속 시간, 마우스 버튼의 자리(누른 곳 / 고정)를
바꾸는 작은 카드가 뜬다. 편집 모드가 아니면 오버레이는 클릭을 통과시키고 표지는 반투명 칩으로만
보인다. `매핑 표시 켬/끔`으로 표지를 숨길 수 있다. 일시 중지 중에는 표지가 흐려지고 위쪽
가운데에 `매핑 일시 중지 (F12)` 칩이 뜬다(DESIGN.md 8절).

**동작의 종류와 화면 말**: 탭(`누르면 터치`), 홀드(`누르는 동안 터치 유지`, 탭 카드의 토글),
조이스틱(`방향키 넷을 가상 스틱으로`, 기본 키는 WASD 또는 방향키 중 택일), 스와이프(`끌기`),
마우스 버튼(`왼쪽 버튼`, `오른쪽 버튼`, `가운데 버튼`을 `누른 자리` 또는 `고정 자리`에), 휠
(`휠 위`, `휠 아래`를 끌기로), 통과(`운영체제로 그대로 보냄`).

## 5. 표시 (S5)

네 절이다. 각 행의 도움 문장은 적용 시점만 말한다.

- **해상도**: 프리셋 카드 세 장(1280x720, 1920x1080, 세로 720x1280)과 `사용자 지정`(폭, 높이,
  DPI 입력. 폭과 높이는 640~7680, DPI 120~640). 각 카드는 해상도, DPI, 방향을 보이고 `적용`을
  누르면 운영체제의 화면 크기와 밀도를 바꾸고 다음 부팅의 부팅 인자를 맞춘다. 크기와 밀도만
  바뀌는 적용은 `즉시 적용할 수 있습니다.` 방향이 바뀌는 카드에는 `방향을 바꾸려면 운영체제를
  다시 시작해야 합니다.`
- **주사율**: `60 Hz (기본)`, `75 Hz`, `90 Hz`, `120 Hz`, `144 Hz`, `사용자 지정`(30~240). 도움
  문장 `다시 시작해야 적용됩니다.` 값은 가상 머신의 디스플레이 정보(EDID)로 운영체제에 전달된다
  (`ARCHITECTURE.md` 8.4절). 높은 값이 실제 프레임으로 이어지는지는 게임과 GPU에 달렸고, 그
  사실은 화면에 적지 않고 `KNOWN_LIMITATIONS.md`에 적는다.
- **수직 동기화**: `끔`, `켬`, `적응형`. 이 행은 `DisplayView.vsync_supported`가 참일 때만 있다
  (자체 패치된 가상 머신에서만). 도움 문장 `다시 시작해야 적용됩니다.`
- **배율**: `창에 맞춤` / `1:1`. 도움 문장 `창에 맞춤은 창 크기에 따라 화면을 늘리거나 줄입니다.
  1:1은 픽셀을 그대로 보입니다.`

## 6. 설정 (S6)

절 제목 아래 설정 행(라벨과 도움 문장 왼쪽, 컨트롤 오른쪽 고정 폭)이 이어진다. 카드 없음.
운영체제 절의 값은 `다시 시작해야 적용됩니다.`

- **운영체제**: `메모리`(슬라이더, 4 GiB부터 `SettingsView.memory_mib_max`까지, 기본 8 GiB. 상한은
  호스트 메모리에서 온다), `프로세서 코어`(2부터 `vcpus_max`까지, 기본 4. 상한은 호스트 논리
  프로세서 수), `그래픽`(도움 문장 `하드웨어 가속을 기본적으로 사용합니다. 화면이 검게 나오거나
  깨질 때만 소프트웨어 렌더링을 사용하십시오. 소프트웨어 렌더링은 성능을 저하시킵니다.`),
  `창을 닫을 때`(`운영체제 끄기` 기본 / `트레이로 내리기`).
- **설치된 운영체제**: 만든 운영체제 목록(이름, 안드로이드 버전, 디스크 크기, 마지막 실행,
  확인된 기능 수)과 `시작할 운영체제`, `새 운영체제 설치`(S1.4의 이미지 카드와 디스크 크기
  선택을 대화상자로), `다시 설치`(디스크를 지우고 같은 이미지로 처음부터 설치한다는 확인 한
  줄), `삭제`(디스크 파일까지 지운다는 확인 한 줄). 이미지 목록은 갱신으로 늘어난다는 한 줄.
- **Google 계정**(2026-09-27 저녁, 사용자 요구: 사용자가 겪는 절차를 R8 안에서 가장 짧게): 운영체제가
  실행 중일 때 보인다. 첫 문장 `이 운영체제는 Google 인증 기기가 아닙니다. Google 계정으로 로그인하려면
  기기 ID를 Google에 한 번 등록해야 합니다.` 상태는 넷이고 스냅숏의 `device_id`,
  `registration_opened_at`, `google_accounts`로 정한다.
  1. 기기 ID 없음(부팅 직후): 회색 램프와 `기기 ID를 읽는 중입니다. 운영체제가 Google 서버와 첫 교신을
     마치면 나타납니다.` 버튼 없음.
  2. 기기 ID 있음, 등록 전: 기기 ID(16진수, 등록 페이지가 받는 형식)와 `복사`, `등록 페이지 열기`(ID를
     복사한 뒤 기본 브라우저를 연다), 도움말 링크(`open_help { googleAccount }`).
  3. 등록 페이지를 연 뒤(`registration_opened_at` 있음, 계정 없음): 주황 램프, `등록한 뒤 약 10분이
     지나면 계정을 추가할 수 있습니다.`와 연 시각(`HH:MM에 열었습니다`), `계정 추가 화면 열기`
     (`google_account_add_open`, 운영체제 안의 계정 추가 화면이 바로 열린다), `등록 페이지 다시 열기`.
  4. 계정 있음(`google_accounts` ≥ 1): 초록 램프, `Google 계정 n개가 로그인되어 있습니다.`,
     `계정 추가 화면 열기`만 남는다.
  어느 상태에서나 마지막 줄은 `등록해도 Play 스토어와 인앱 결제는 보장되지 않습니다.`(R8). 계정과
  비밀번호는 운영체제 창 안에서 입력하며 제품은 그 값을 다루지 않는다. `add_account_supported`가
  거짓이면 `계정 추가 화면 열기` 대신 `운영체제의 설정 → 계정에서 추가하십시오.` 한 줄. 왜 제품이
  대신 등록하지 않는지는 10절 4번, 사용자 안내는 `docs/help/google-account.md`.
- **입력**: `매핑 일시 중지 단축키`(기본 F12, 키 하나 눌러 바꿈), `매핑 표지 기본 표시`, `게임별
  자동 적용` 토글.
- **고급**: `adb 연결`(주소 `127.0.0.1:5555`와 `복사`. 도움 문장 `adb로 연결한 프로그램은 운영체제
  안의 모든 앱과 데이터를 다룰 수 있습니다. 신뢰하는 프로그램만 연결하십시오.`), `다른 PC에서
  연결 허용` 토글(기본 끔. 켜면 경고 상자 `같은 네트워크의 누구나 이 운영체제에 접근할 수
  있습니다.`), `루트 권한`(토글. 도움 문장 `앱이 루트 권한을 요청할 수 있게 합니다. 일부 게임과
  결제 기능은 루트가 켜진 기기에서 동작하지 않습니다.` 운영체제가 실행 중일 때만 바꿀 수 있다).
- **저장 위치**: OME 홈 경로와 `폴더 열기`, 디스크 사용량.
- **업데이트**: 현재 버전, `업데이트 확인`, 새 버전이 있으면 버전과 릴리스 노트 링크와
  `다운로드 후 설치`. 자동 확인 켬/끔.
- **진단**: `진단 묶음 내보내기`, `로그 폴더 열기`, 최근 이벤트 다섯 줄.
- **정보**: 제품 이름과 버전, 라이선스(GPL-2.0-or-later), 제3자 고지, `가상 머신 소스 코드`와
  `소스 코드 받기`(R4). `처음부터 다시 설정`은 없다.

## 7. 트레이와 알림 (S7)

트레이 메뉴: `창 보이기`, `시작`(운영체제가 꺼져 있을 때) 또는 `끄기`(실행 중일 때), `종료`.
토스트는 세 종류만 있다. 운영체제가 예기치 않게 끝났을 때(`로그 보기` 동작 포함), 업데이트가
있을 때, 긴 다운로드가 끝났을 때. 토스트는 윈도우 알림 센터에 남고 앱은 알림 이력을 따로
두지 않는다.

## 8. 막힘 화면 (S8)

마법사 밖에서도 나올 수 있는 전체 본문 상태(`AppSnapshot.blocker`). 각 화면은 원인 한 문장,
다음 행동 한 문장, 버튼 하나다.

- 가상화 꺼짐: `이 PC의 BIOS 설정에서 가상화가 꺼져 있습니다.` / `PC를 다시 시작해 BIOS 설정에서
  가상화(Intel VT-x 또는 AMD-V)를 켠 뒤 이 앱을 다시 여십시오.` 버튼 `켜는 방법`(문서를 연다),
  `다시 확인`. 아래에 작게 `BIOS 메뉴 이름은 PC 제조사마다 다릅니다.`
- 가상 머신 파일 없음: `가상 머신 구성 요소를 찾을 수 없습니다.` / `앱을 다시 설치하십시오.`
- 하이퍼바이저 꺼짐: `하이퍼바이저가 꺼져 있습니다.` / 버튼 `활성화`(S1.2로 간다).

## 9. 문구와 상태 규칙

- 모든 오류는 `AppIssue`의 문장과 다음 행동을 그대로 쓴다. 원문은 `세부 정보` 펼침 안에만 있다.
- 상태 점이나 확인 기호 옆 글자는 명사구다(`시작 가능`, `부팅 중`, `실행 중`, `가상 머신 시작`).
  성공과 진행은 기호가 말하므로 `~했습니다`, `~하는 중입니다`를 옆에 두지 않는다.
- 판정은 판정으로 쓴다. 검사를 했다고 서술하지 않고 결과를 말한다(`이 PC에서는 Open Mobile
  Emulator를 사용할 수 있습니다.`). 아무것도 바꾸지 않는다, 확인 창이 한 번 더 뜬다, 직접 눌러야
  한다 같은 절차 서술은 쓰지 않는다. 요구 사항은 요구 사항으로 쓴다(`활성화 시 관리자 권한이
  필요합니다.`).
- 낱말은 다른 제품이 쓰는 말을 쓴다. `다운로드`, `무결성 확인`, `스냅샷`, `크래시`,
  `하이퍼바이저`, `운영체제`. 순화어를 새로 만들지 않는다.
- 문장은 합니다체, 지시는 `-십시오`. 버튼과 메뉴는 명사형(`활성화`, `다시 확인`).
- 게임 이름, 캐릭터, 스크린샷은 제품 화면과 목업에 넣지 않는다. 목업의 앱 목록은 "샘플 앱"
  같은 중립 이름을 쓴다(R6).
- 숫자는 `tabular-nums`, 단위는 띄어 쓴다(2.3 GB, 58 fps, 120 Hz).

이 규칙의 근거와 예는 `DESIGN.md` 9절에 있다.

## 10. 사용자 결정 (2026-09-27)

2026-09-26에 물은 여섯 가지의 답과, 같은 날 사용자가 더한 요구다.

1. 레일은 아이콘 + 라벨(64px)이다.
2. fps와 호스트 CPU는 기본 숨김, 설정에서 켠다.
3. 창을 닫을 때 기본 동작은 **운영체제 끄기**다. 트레이로 내리기는 설정이다. 권고(트레이)는
   사용자가 껐다고 믿는 운영체제가 메모리 8 GB를 계속 차지하는 문제를 낳으므로 뒤집었다.
4. 구글 계정 안내는 첫 실행에서 뺀다. 사용자의 원칙은 "돈이 반드시 드는 일이 아니면 제품이
   한다"이고, 이 일은 돈이 드는 일이 아니다. 그런데도 제품이 등록을 대신하지 못하는 이유는
   다음과 같다. 구글의 비인증 기기 등록 폼은 사용자 본인의 구글 계정으로 로그인한 브라우저
   세션에서만 제출할 수 있고, 제품이 그 세션이나 계정 정보를 쥐는 순간 제품이 사용자 계정의
   자격 증명을 다루는 프로그램이 된다. 다른 상용 에뮬레이터가 이 단계를 요구하지 않는 이유는
   인증받은 실제 휴대폰의 기기 지문(`ro.build.fingerprint` 등)을 복사해 구글 서버가 그 휴대폰으로
   여기게 하기 때문인데, 그것은 D8(평범한 x86_64 태블릿 프로필, 변경 불가)과 R8(인증 우회 금지)이
   막는 일이다. 그래서 제품이 할 수 있는 최대는 기기 ID를 읽어 클립보드에 넣고 등록 페이지를
   여는 것이고, 그 일은 필요한 사람에게만 보이도록 설정의 Google 계정 절로 옮겼다. 구글 계정
   없이도 게임은 게스트 계정으로 돈다(M0 증거). D8을 다시 열지는 사용자의 결정이다.
5. 매핑 일시 중지 단축키는 F12다.
6. 이미지 카드는 최신 버전이 앞이고, 기본 선택은 알파가 아닌 가장 새 버전이다. 알파는 출시
   28일 안이거나 이 프로젝트가 트릭컬 실행 증거를 확보하지 못한 버전이다. 계산은 Rust가 한다
   (`GuestImageSummary.recommended`, `ARCHITECTURE.md` 8.2절). 지금은 안드로이드 13 하나가
   검증되어 있어 결과는 같고, 15가 검증되면 자동으로 15가 기본이 된다.

사용자가 더한 요구와 처리:

- **하드웨어 한도**: 32 GB 메모리, 16 vCPU 같은 값을 막을 이유가 없다. QEMU는 `smp.cpus`를 WHPX
  파티션의 프로세서 수로 그대로 넘기고 q35의 상한은 4096이며, 메모리 상한은 호스트 물리 메모리다.
  설정의 상한은 호스트에서 읽는다(8.5절). 근거는 `docs/evidence/M2/sizing-20260927/`.
- **고해상도, 고주사율, 수직 동기화**: 5절 표시 화면. 주사율은 EDID `refresh_rate`(QEMU 11.1이
  이미 갖고 있다), 수직 동기화는 QEMU SDL 디스플레이의 고정값을 옵션으로 여는 자체 패치가
  필요하다(R4의 소스 묶음에 들어간다).
- **DirectX 12**: 운영체제 안의 앱은 OpenGL ES나 Vulkan으로 그리고 DirectX를 말하지 않는다.
  DirectX는 호스트 쪽 번역기의 백엔드로만 등장한다(ANGLE의 D3D11). 장기 경로는 gfxstream으로
  가서 게스트 Vulkan을 호스트 Vulkan(NVIDIA 네이티브 드라이버)에 그대로 넘기는 것이고, 그것이
  "OpenGL에 갇히지 않는" 실제 방법이다. 조사 결과는 `docs/DECISION-gpu-roadmap.md`.
- **루팅과 adb**: 6절 고급 절. adb는 경고와 함께, 다른 PC 연결은 기본 끔.

## 11. 구현 상태 (2026-09-27 저녁)

- 화면은 `host/ui/src/screens/`에 전부 있다. 마법사 일곱 단계, 막힘 화면 세 가지, 무대의 모든
  상태, 앱, 입력(레일 화면), 표시(주사율과 수직 동기화 절 포함), 설정(설치된 운영체제, 고급 절
  포함). 컴포넌트는 `host/ui/src/components/`, 문구 도우미는 `presentation.ts`와 `input-profile.ts`.
